# 召喚獣コンテキスト

召喚獣、召喚、ステータス、能力、召喚フィールドを扱う文脈。

## 参照元

- Wikipedia「バカとテストと召喚獣」では、試験召喚獣は召喚者をデフォルメした分身で、試験召喚システムにより召喚フィールド内で出現すると説明されている。
- 同ページでは、召喚獣の力は該当科目の直近点数に比例し、召喚フィールドは教師が展開する範囲として説明されている。

## 用語

### 試験召喚システム

- 定義: 試験の点数を召喚獣の力に変換し、召喚獣の表示・バトル・学習意欲向上へつなげる仕組み。
- アクター: 生徒、教師、学校管理者。
- 目的: 学習成果をゲーム的な体験に変換し、生徒の学習意欲を高める。
- 文脈: プロダクト全体、試験、召喚獣、バトル。
- ルール:
  - Railsが点数を正本として管理し、召喚獣ステータスを計算する。
  - Go Game Serverはバトル中の一時状態だけを扱い、DBへ直接接続しない。
  - MVPでは音声認識による召喚は扱わず、画面表示として召喚獣を扱う。
- 含まないもの: 採点AI、3Dワールド、学校外SNS。
- 例: 試験点数からHP・攻撃・防御・素早さを計算する仕組み。
- 反例: 単なる成績管理表、通常のクイズアプリ。
- 関連語: 試験、点数、召喚獣、試召戦争。
- 実装・テストへの影響: Rails APIの点数登録後に召喚獣ステータスが再計算されることをテストする。
- 未決事項: 召喚獣の見た目生成、進化、装備、スキルをいつ扱うか。

### 試験召喚獣

- 定義: 生徒の試験結果から算出されたステータスを持つ、生徒に紐づくゲーム上の分身。
- アクター: 生徒、教師。
- 目的: 点数を視覚的・ゲーム的に表現し、バトルに参加させる。
- 文脈: 生徒画面、バトル画面、召喚獣ステータス表示。
- ルール:
  - 原作・アニメでは召喚者をデフォルメした分身として扱われる。
  - MVPでは1生徒につき1体の召喚獣を表示・計算対象とする。
  - MVPでは見た目の進化、装備、スキルツリーは扱わない。
  - 召喚獣の強さは生徒の点数から計算される。
- 含まないもの: 生徒本人、通常のアバター、教師の管理画面。
- 例: 数学82点を反映した召喚獣。
- 反例: ログインユーザーのプロフィール画像。
- 関連語: 召喚、召喚獣ステータス、点数、バトル。
- 実装・テストへの影響: 生徒IDと召喚獣ステータスの対応、点数更新後の再計算、バトル開始時の読み込みをテストする。
- 未決事項: 召喚獣の名前、外見、性格をユーザーが編集できるか。

### 召喚

- 定義: 生徒の召喚獣を画面上またはバトル上に出現させる操作。
- アクター: 生徒、教師、Go Game Server。
- 目的: 生徒の点数に基づく召喚獣を確認・対戦に参加させる。
- 文脈: 生徒画面、バトル開始、将来の音声起動。
- ルール:
  - 原作・アニメの起動ワードは「試験召喚獣召喚・試獣召喚（サモン）！」。
  - MVPでは音声認識による起動ワード検知を実装しない。
  - MVPでは画面遷移やバトル開始時に召喚獣を表示する。
- 含まないもの: アカウント作成、試験登録、採点。
- 例: バトル画面で自分の召喚獣を表示する。
- 反例: 教師が点数を入力する操作。
- 関連語: 試験召喚獣、召喚フィールド、起動ワード。
- 実装・テストへの影響: バトル開始時に対象プレイヤーの召喚獣ステータスを取得できることをテストする。
- 未決事項: 起動ワードをUI表示だけにするか、将来音声認識で実際に使うか。

### 召喚獣ステータス

- 定義: 点数から算出され、バトルに使われる召喚獣の能力値。
- アクター: 生徒、教師、Go Game Server。
- 目的: 学習成果をバトル上の強さへ変換する。
- 文脈: 点数登録後の再計算、召喚獣表示、バトル開始データ。
- ルール:
  - MVPではHP、攻撃、防御、素早さを扱う。
  - 点数は100点換算してステータス計算に使う。
  - 具体的な計算式は単純な一次式から始め、ゲームバランス調整は後続フェーズで行う。
  - Railsが計算し、Go Game Serverは開始時データとして利用する。
- 含まないもの: 成績としての点数そのもの、装備、スキルツリー。
- 例: HP120、攻撃30、防御10、素早さ5。
- 反例: 数学82点、試験名、登録日。
- 関連語: 点数、試験召喚獣、HP、バトル。
- 実装・テストへの影響: ステータス計算の単体テスト、APIレスポンス、バトル開始時の整合性をテストする。
- 未決事項: 科目別点数をどのステータスへどう割り当てるか。

### 召喚フィールド

- 定義: 原作・アニメで召喚獣が使用可能になる範囲。
- アクター: 教師、生徒。
- 目的: 召喚獣の使用範囲と戦闘成立条件を制御する。
- 文脈: 原作・アニメ準拠の召喚、将来の3Dフィールド・試召戦争。
- ルール:
  - 原作・アニメでは教師が展開する範囲内で召喚獣を使用できる。
  - MVPの1対1バトルでは物理的な範囲判定を扱わない。
  - 将来の3Dフィールドでは、バトルモードへ入る領域や成立条件として再検討する。
- 含まないもの: WebSocketのバトルルーム、画面レイアウト、クラス設備。
- 例: 教師の周囲に展開される召喚可能範囲。
- 反例: Rails APIの認証スコープ。
- 関連語: 召喚、教師、試召戦争、3Dフィールド。
- 実装・テストへの影響: MVPでは実装しない。将来、位置同期を扱う場合はGo Game Serverの責務になる。
- 未決事項: 3Dフィールド上で召喚可能範囲を実装するか。

### 腕輪

- 定義: 原作・アニメで、点数を消費して召喚システムに特殊な介入を行う補助アイテム。
- アクター: 生徒。
- 目的: 通常召喚以外の特殊能力や戦術を成立させる。
- 文脈: 原作・アニメ準拠の特殊ルール、将来スコープ。
- ルール:
  - 原作では単科目400点以上の生徒に腕輪が与えられる設定がある。
  - 白金の腕輪、黒金の腕輪など複数種がある。
  - MVPでは実装しない。
- 含まないもの: 通常ステータス、通常攻撃、ログイン権限。
- 例: 代理召喚型の腕輪、同時召喚型の腕輪。
- 反例: 召喚獣のHP、防御。
- 関連語: 点数、召喚、特殊能力、試召戦争。
- 実装・テストへの影響: 将来実装時は、成績点数の消費ではなくバトル中リソース消費として扱う可能性が高い。
- 未決事項: 腕輪を教育プロダクトに入れるか。入れる場合、点数消費を成績低下として見せない設計が必要。

### 物理干渉能力

- 定義: 原作・アニメで、一部の召喚獣が物体に触れたり破壊したりできる能力。
- アクター: 観察処分者、教師。
- 目的: 召喚獣を雑用や物理的な作業に使う例外ルールを表す。
- 文脈: 原作・アニメ準拠、将来の演出・特殊能力。
- ルール:
  - 原作・アニメでは観察処分者や教師の召喚獣が持つ例外能力として説明される。
  - MVPでは実装しない。
- 含まないもの: 通常攻撃、画面上のクリック操作。
- 例: 荷物運びができる召喚獣。
- 反例: 他の召喚獣にだけ攻撃できる通常召喚獣。
- 関連語: 観察処分者、召喚獣、フィードバック。
- 実装・テストへの影響: MVPでは対象外。将来の3D演出では、ゲーム内オブジェクトへの干渉可否として扱う。
- 未決事項: 観察処分者をプロダクトのロールや称号として採用するか。
