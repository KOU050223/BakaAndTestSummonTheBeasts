# アカウントコンテキスト

ユーザー、アカウント、認証、プロフィールを扱う文脈。

## 用語

### ユーザー

- 定義: システムへログインし、役割に応じた操作を行う人。
- アクター: 生徒、教師、学校管理者。
- 目的: 成績確認、試験管理、クラス管理、バトル参加などを本人の権限で行う。
- 文脈: React Frontend、Rails REST API、Go Game Server の認証・認可。
- ルール:
  - Railsが認証情報の正本を管理する。
  - REST APIとWebSocket接続では、認証済みユーザーを識別できる必要がある。
  - ユーザーの役割によって利用できる操作が変わる。
- 含まないもの: 召喚獣、クラス、試験結果そのもの。
- 例: 生徒ユーザー、教師ユーザー、学校管理者ユーザー。
- 反例: 未ログインの閲覧者、外部システムのサービスアカウント。
- 関連語: アカウント、ロール、プロフィール。
- 実装・テストへの影響: `role` による権限制御、WebSocket接続時のユーザー特定、本人以外の成績参照制限をテストする。
- 未決事項: 学校外の保護者、見学者、運営者をユーザーとして扱うか。

### ロール

- 定義: ユーザーがシステム内で実行できる操作範囲を決める役割。
- アクター: 生徒、教師、学校管理者。
- 目的: 成績・試験・クラス・バトルの操作権限を分離する。
- 文脈: 認証後のAPI認可、画面表示制御。
- ルール:
  - 生徒は自分の点数、召喚獣、参加バトルを確認する。
  - 教師は担当する試験、点数、クラスを管理する。
  - 学校管理者はユーザーとクラス設定を管理する。
- 含まないもの: クラス内の代表、バトル中の役割、召喚獣の能力。
- 例: `student`, `teacher`, `school_admin`。
- 反例: Fクラス、Aクラス、クラス代表。
- 関連語: ユーザー、権限、プロフィール。
- 実装・テストへの影響: APIごとに許可ロールと拒否ロールのテストを分ける。
- 未決事項: 教師が複数クラス・複数科目を担当する場合の権限範囲。
