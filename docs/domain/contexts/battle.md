# バトルコンテキスト

バトル、召喚フィールド、行動、勝敗、状態、試召戦争を扱う文脈。

## 参照元

- Wikipedia「バカとテストと召喚獣」では、試験召喚戦争はクラス間抗争で、召喚獣の力は該当科目の直近点数に比例すると説明されている。
- 同ページでは、科目担当教師の立ち会い（召喚フィールド）の範囲内でその科目の召喚獣を呼び出せるルールが説明されている。
- 同ページでは、クラス代表の敗北で戦争の勝敗が決まり、勝敗によりクラス設備が変わるルールが説明されている。

## バトル方式の方針（MVP）

MVP のバトルは **ローカル AR 上のリアルタイムアクション** として実装する。
固定 tick（30Hz）でサーバー（Go Game Server）が権威的に状態を進行させ、プレイヤーは
移動・サモン・攻撃の入力意図のみを送る。原作の「召喚フィールド」ルールを中核に据える。

## 用語

### バトル

- 定義: 2人のプレイヤーが、AR 空間に展開された複数科目の召喚フィールドの上で、召喚獣を動かして勝敗を決めるリアルタイム対戦。
- アクター: 生徒、教師、Go Game Server。
- 目的: 学習成果（科目ごとの成績）をゲーム体験に変換し、生徒の学習意欲を高める。
- 文脈: MVP の1対1リアルタイムアクションバトル、React Battle UI（R3F + WebXR）、Go Game Server。
- ルール:
  - MVP では1対1のみ扱う。
  - バトルごとに複数（3〜4）の対戦科目を選び、各科目の召喚フィールドを AR 床に配置する。
  - プレイヤーは移動・サモン・攻撃の3操作を持つ。
  - 手持ちのどれか1科目の召喚獣 HP が0になったプレイヤーが敗北する（即時敗北）。
  - Go Game Server が固定 tick で位置・向き・HP・フェーズを権威的に同期し、結果を Rails API へ保存する。
- 含まないもの: クラス設備交換、宣戦布告（クラス対抗）、補充試験、逃げる操作。
- 例: 数学・英語・理科の3フィールドを配置した生徒A対生徒Bのバトル。
- 反例: 試験作成、点数入力、成績フィードバックだけの画面。
- 関連語: 試召戦争、召喚フィールド、行動、HP、勝敗。
- 実装・テストへの影響: WebSocket 接続、tick 進行、移動・攻撃判定、HP 同期、結果保存をテストする。

### 召喚フィールド

- 定義: 科目担当教師を中心とする円形の領域で、その内側ではその科目の召喚獣のみ召喚・戦闘できる。
- アクター: 生徒、教師（仮想 NPC として配置）、Go Game Server。
- 目的: 原作の「教師の立ち会いで召喚できる」ルールを再現し、移動に戦術的意味を与える。
- 文脈: AR 空間に展開されるバトルフィールド、サモン、科目自動切替。
- ルール:
  - バトルごとに複数の召喚フィールド（科目＝中心の先生）を配置する。
  - プレイヤーがフィールド円の内側に入ると、その科目に自動で切り替わる。
  - フィールドの外（中立地帯）では召喚も戦闘もできない。
  - 各フィールドは中心座標・半径・科目を持つ（Go サーバーが権威的に保持）。
- 含まないもの: 現実の GPS、現実の教師の物理位置、クラス設備。
- 例: 半径数メートルの「数学フィールド」「英語フィールド」を AR 床に並べる。
- 反例: 画面全体で常に全科目が使える状態。
- 関連語: 対戦科目、サモン、移動、教師。
- 実装・テストへの影響: 円内外判定、科目自動切替、ゾーン外での召喚・攻撃の拒否をテストする。
- 未決事項: フィールド配置（座標・半径）をバトル作成時に固定するか、ランダム生成するか。

### 対戦科目

- 定義: バトルで召喚獣ステータスや勝負条件の根拠にする科目。各召喚フィールドに対応する。
- アクター: 教師、生徒、Go Game Server。
- 目的: どの学習成果をバトルに反映するかを明確にする。
- 文脈: バトル作成、召喚フィールド配置、バトル開始データ、勝敗判定。
- ルール:
  - バトル作成時に複数（3〜4）指定する。
  - 各科目につき、両プレイヤーの召喚獣ステータス（科目別）をスナップショットする。
  - 指定科目の点数がない生徒の扱いは未決（0点扱いを暫定とする）。
- 含まないもの: 複数科目合算、総合科目、クラスランク。
- 例: 数学・英語・理科を対戦科目に選ぶ。
- 反例: Fクラス対Aクラス、HP。
- 関連語: 科目、点数、召喚フィールド、召喚獣ステータス。
- 実装・テストへの影響: 各対戦科目に対応する最新点数・ステータスを使うことをテストする。

### 移動

- 定義: プレイヤーが AR 床上で召喚獣の位置と向きを変える操作。
- アクター: 生徒、Go Game Server。
- 目的: 有利な召喚フィールドを取り、攻撃の間合いと向きを作る。
- 文脈: リアルタイムアクション、召喚フィールドの自動切替、攻撃判定。
- ルール:
  - MVP では離散的な方向ボタン（押下状態）で移動する（将来スティック連続移動へ拡張）。
  - サーバーが毎 tick、移動速度（素早さに比例）に応じて位置・向きを更新する。
  - 移動でフィールドに入る／出ることで使用科目が変わる。
- 含まないもの: 現実空間の歩行（GPS）、ワープ、瞬間移動。
- 例: 前進ボタンを押して数学フィールドへ入る。
- 関連語: 召喚フィールド、素早さ、向き、攻撃。
- 実装・テストへの影響: 入力状態の反映、移動速度計算、フィールド境界の出入りをテストする。
- 未決事項: 連続移動（スティック）導入時の補間と高頻度同期の扱い。

### サモン（召喚）

- 定義: 今いる召喚フィールドの科目の召喚獣を AR 空間に出現させる操作。
- アクター: 生徒、Go Game Server。
- 目的: フィールドの科目に応じた召喚獣を戦場へ顕現させる。
- 文脈: 召喚フィールド、戦闘可否、再召喚。
- ルール:
  - フィールド内でのみ召喚できる。中立地帯では召喚不可。
  - 撃破された召喚獣はサモンで再召喚できる（ただし HP0 は即敗北のため再召喚は温存運用が主目的）。
- 含まないもの: スキル発動、属性変化、腕輪能力。
- 例: 数学フィールド内でサモンを押し、数学召喚獣を出す。
- 反例: フィールド外での召喚。
- 関連語: 召喚フィールド、召喚獣、HP。
- 実装・テストへの影響: フィールド外召喚の拒否、再召喚の挙動をテストする。

### 行動（攻撃）

- 定義: 召喚獣が相手にダメージを与えるバトル操作。
- アクター: 生徒、Go Game Server。
- 目的: バトルの進行と HP 変化を発生させる。
- 文脈: バトル UI、WebSocket メッセージ、ダメージ計算。
- ルール:
  - MVP では通常攻撃のみ扱う。
  - サーバー権威で判定する：距離 ≤ レンジ かつ 相手が攻撃者の正面の一定角度内なら命中。
  - ダメージ = max(1, attack - defense)。
  - 攻撃間隔（クールタイム）は素早さに反比例する。
  - フィールド外では攻撃できない。
- 含まないもの: 逃げる、スキル、属性、腕輪能力。
- 例: 間合い内かつ正面に相手を捉えた状態での通常攻撃。
- 反例: 採点、召喚獣ステータス確認。
- 関連語: ダメージ、HP、間合い、向き、素早さ。
- 実装・テストへの影響: 距離・向きの命中判定、ダメージ式、クールタイム、行動種別の将来拡張をテストする。

### HP

- 定義: バトル中に各科目の召喚獣が戦闘継続できる残量を表す一時的な値。
- アクター: 生徒、Go Game Server。
- 目的: 勝敗条件を判定する。
- 文脈: バトル中の一時状態、科目別召喚獣ステータス。
- ルール:
  - 科目（召喚獣）ごとに個別の HP を持つ。初期 HP は科目別召喚獣ステータスから決める。
  - いずれか1科目の HP が0になったら、そのプレイヤーは即敗北する。
  - 0未満には丸める。HP 減少を成績点数の減点として保存しない。
- 含まないもの: 成績としての点数、満点、経験値。
- 例: 数学召喚獣 HP142、英語召喚獣 HP108、…のうち1つが0。
- 反例: 数学82点、英語74点。
- 関連語: 点数、召喚獣ステータス、勝敗。
- 実装・テストへの影響: 科目別 HP 同期、0未満丸め、いずれか0で勝敗確定、確定後の追加入力拒否をテストする。
- 未決事項: 引き分け、タイムアウト、自滅ダメージを扱うか。

### 勝敗

- 定義: バトルまたは試召戦争の結果。
- アクター: 生徒、教師、Go Game Server、Rails API。
- 目的: バトルを終了し、履歴や将来の報酬・ペナルティへ反映する。
- 文脈: MVP の1対1バトル結果、将来の試召戦争結果。
- ルール:
  - MVP では、相手の手持ちのいずれか1科目召喚獣の HP を0にしたプレイヤーが勝利する。
  - 結果（勝者・敗者・決着ターン相当・ログ）を Rails API へ冪等に保存する。
  - 原作・アニメの試召戦争ではクラス代表の敗北が勝敗決定条件になる（将来）。
- 含まないもの: 点数の高低だけの比較、クラス設備そのもの。
- 例: プレイヤーA勝利、プレイヤーB敗北（B の理科召喚獣が撃破）。
- 反例: 試験で80点を取ること。
- 関連語: バトル、HP、召喚フィールド、試召戦争。
- 実装・テストへの影響: 結果保存の冪等性、勝敗確定後の状態変更禁止をテストする。
- 未決事項: 引き分け、無効試合、切断負けを扱うか。

### 試召戦争

- 定義: 原作・アニメのクラス対抗戦を参照した、召喚獣による対抗戦。
- アクター: 生徒、教師、学校管理者。
- 目的: クラス単位の目標と報酬を作り、学習への参加動機を高める。
- 文脈: 将来のクラス対抗バトル、クラス設備攻略。
- ルール:
  - 原作・アニメではクラス対抗戦を原則とする。
  - 原作・アニメでは科目担当教師の立ち会い（召喚フィールド）により召喚が可能になる。
  - 原作・アニメではクラス代表の敗北で勝敗が決まる。
  - MVP ではクラス対抗の試召戦争は実装しない（1対1バトルのみ）。
- 含まないもの: MVP の単純な1対1バトル、通常の試験。
- 例: FクラスがAクラスへ挑むクラス対抗戦。
- 反例: 教師が数学小テストの点数を入力すること。
- 関連語: クラス、クラス代表、クラス設備、宣戦布告。
- 実装・テストへの影響: 将来実装時は、バトル結果、クラス設備、代表、戦争状態を一貫して扱う集約が必要。
- 未決事項: 教育現場向けに「戦争」という名称をそのまま使うか、「クラス対抗戦」などへ置き換えるか。

### 補習

- 定義: 原作・アニメで、戦死や戦闘放棄した生徒が受ける学習ペナルティ。
- アクター: 生徒、教師。
- 目的: 試召戦争のペナルティと学習機会を結びつける。
- 文脈: 原作・アニメ準拠の試召戦争、将来の学習支援。
- ルール:
  - MVP では実装しない。
  - 将来実装する場合、罰ではなく学習支援タスクとして設計する必要がある。
- 含まないもの: 通常授業、試験そのもの、バトル履歴。
- 例: 敗北後に弱点科目の復習課題を出す。
- 反例: 単なる HP 回復アイテム。
- 関連語: 補充試験、成績フィードバック。
- 実装・テストへの影響: 将来実装時は、生徒の心理的安全性と教育方針に合わせて名称・表示を検討する。
- 未決事項: 実教育導入で「補習」をペナルティ扱いにするか、復習セッション扱いにするか。

### 宣戦布告

- 定義: 原作・アニメで、クラス対抗の試召戦争を開始する申し込み。
- アクター: クラス、生徒、教師。
- 目的: クラス間の対抗戦を正式に開始する。
- 文脈: 将来の試召戦争、クラス設備攻略。
- ルール:
  - 原作・アニメでは上位クラスは宣戦布告を断れない。
  - MVP では実装しない。
- 含まないもの: 1対1バトル作成、フレンド申請、通知。
- 例: FクラスがAクラスへ挑む申し込み。
- 反例: 教師が個人バトルを作成すること。
- 関連語: 試召戦争、クラス、クラス代表、クラス設備。
- 実装・テストへの影響: 将来実装時は、申し込み、受理、拒否不可条件、開始時刻、参加者確定を状態遷移として設計する。
- 未決事項: 教育現場向けに「宣戦布告」という名称を使うか、「対抗戦申請」に置き換えるか。
