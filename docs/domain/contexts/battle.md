# バトルコンテキスト

バトル、ターン、行動、勝敗、状態、試召戦争を扱う文脈。

## 参照元

- Wikipedia「バカとテストと召喚獣」では、試験召喚戦争はクラス間抗争で、召喚獣の力は該当科目の直近点数に比例すると説明されている。
- 同ページでは、クラス代表の敗北で戦争の勝敗が決まり、勝敗によりクラス設備が変わるルールが説明されている。

## 用語

### バトル

- 定義: 召喚獣同士が、指定された対戦科目のステータスをもとに勝敗を決める対戦。
- アクター: 生徒、教師、Go Game Server。
- 目的: 学習成果をゲーム体験に変換し、生徒の学習意欲を高める。
- 文脈: MVPの1対1ターン制バトル、React Battle UI、Go Game Server。
- ルール:
  - MVPでは1対1のみ扱う。
  - バトル作成時に1つの対戦科目を指定する。
  - MVPでは通常攻撃のみ扱う。
  - どちらかのHPが0になったら終了する。
  - Go Game Serverが対戦中の一時状態を管理し、結果をRails APIへ保存する。
- 含まないもの: クラス設備交換、宣戦布告、補充試験、逃げる操作。
- 例: 数学を対戦科目にした生徒A対生徒Bのバトル。
- 反例: 試験作成、点数入力、成績フィードバックだけの画面。
- 関連語: 試召戦争、ターン、行動、HP、勝敗。
- 実装・テストへの影響: WebSocket接続、ターン進行、HP同期、結果保存をテストする。
- 未決事項: 教師が必ずバトルを作成するか、生徒同士で申請できるか。

### 試召戦争

- 定義: 原作・アニメのクラス対抗戦を参照した、召喚獣による対抗戦。
- アクター: 生徒、教師、学校管理者。
- 目的: クラス単位の目標と報酬を作り、学習への参加動機を高める。
- 文脈: 将来のクラス対抗バトル、クラス設備攻略。
- ルール:
  - 原作・アニメではクラス対抗戦を原則とする。
  - 原作・アニメでは科目担当教師の立ち会いにより召喚が可能になる。
  - 原作・アニメではクラス代表の敗北で勝敗が決まる。
  - MVPではクラス対抗の試召戦争は実装しない。
- 含まないもの: MVPの単純な1対1バトル、通常の試験。
- 例: FクラスがAクラスへ挑むクラス対抗戦。
- 反例: 教師が数学小テストの点数を入力すること。
- 関連語: クラス、クラス代表、クラス設備、宣戦布告。
- 実装・テストへの影響: 将来実装時は、バトル結果、クラス設備、代表、戦争状態を一貫して扱う集約が必要。
- 未決事項: 教育現場向けに「戦争」という名称をそのまま使うか、「クラス対抗戦」などへ置き換えるか。

### 対戦科目

- 定義: バトルで召喚獣ステータスや勝負条件の根拠にする科目。
- アクター: 教師、生徒、Go Game Server。
- 目的: どの学習成果をバトルに反映するかを明確にする。
- 文脈: バトル作成、バトル開始データ、勝敗判定。
- ルール:
  - バトル作成時に指定する。
  - MVPでは1バトルにつき1科目とする。
  - 指定科目の点数がない生徒をバトルに参加させるかは未決。
- 含まないもの: 複数科目合算、総合科目、クラスランク。
- 例: 数学バトル、英語バトル。
- 反例: Fクラス対Aクラス、HP。
- 関連語: 科目、点数、バトル、召喚獣ステータス。
- 実装・テストへの影響: 対戦科目に対応する最新点数・ステータスを使うことをテストする。
- 未決事項: 点数未登録の場合に参加不可、0点扱い、仮ステータス扱いのどれにするか。

### ターン

- 定義: バトル中にプレイヤーが行動を選び、結果が反映される進行単位。
- アクター: 生徒、Go Game Server。
- 目的: 1対1バトルを同期し、行動順と結果を明確にする。
- 文脈: MVPのターン制バトル。
- ルール:
  - MVPではボタン操作で行動を選ぶ。
  - Go Game ServerがHP、ターン、行動、フェーズを同期する。
  - 素早さが行動順に影響するかは未決。
- 含まないもの: 学期、試験期間、年度。
- 例: プレイヤーAが通常攻撃を選択し、ダメージが反映される1ターン。
- 反例: 試験の登録日。
- 関連語: 行動、フェーズ、HP、素早さ。
- 実装・テストへの影響: 同時入力、二重入力、切断時のターン状態をテストする。
- 未決事項: 両者同時選択式か、素早さ順の交互行動式か。

### 行動

- 定義: ターン中にプレイヤーが選択するバトル操作。
- アクター: 生徒、Go Game Server。
- 目的: バトルの進行とHP変化を発生させる。
- 文脈: バトルUI、WebSocketメッセージ、ダメージ計算。
- ルール:
  - MVPでは通常攻撃のみ扱う。
  - 逃げる、スキル、属性、腕輪能力はMVPでは扱わない。
- 含まないもの: 試験作成、点数登録、ログイン。
- 例: 通常攻撃。
- 反例: 採点、召喚獣ステータス確認。
- 関連語: ターン、通常攻撃、ダメージ、HP。
- 実装・テストへの影響: MVPでも行動種別は将来拡張できる形で保存・送信する。
- 未決事項: 防御をMVPから入れるか、通常攻撃だけで完全に固定するか。

### HP

- 定義: バトル中に召喚獣が戦闘継続できる残量を表す一時的な値。
- アクター: 生徒、Go Game Server。
- 目的: 勝敗条件を判定する。
- 文脈: バトル中の一時状態、召喚獣ステータス。
- ルール:
  - MVPでは召喚獣ステータスから初期HPを決める。
  - HPが0になった側が敗北する。
  - MVPではHP減少を成績点数の減点として保存しない。
- 含まないもの: 成績としての点数、満点、経験値。
- 例: 初期HP120、残りHP42。
- 反例: 数学82点、英語74点。
- 関連語: 点数、召喚獣ステータス、戦死、勝敗。
- 実装・テストへの影響: HP同期、0未満丸め、勝敗確定後の追加入力拒否をテストする。
- 未決事項: 引き分け、タイムアウト、自滅ダメージを扱うか。

### 勝敗

- 定義: バトルまたは試召戦争の結果。
- アクター: 生徒、教師、Go Game Server、Rails API。
- 目的: バトルを終了し、履歴や将来の報酬・ペナルティへ反映する。
- 文脈: MVPの1対1バトル結果、将来の試召戦争結果。
- ルール:
  - MVPでは相手のHPを0にしたプレイヤーが勝利する。
  - MVPでは結果をRails APIへ保存する。
  - 原作・アニメの試召戦争ではクラス代表の敗北が勝敗決定条件になる。
- 含まないもの: 点数の高低だけの比較、クラス設備そのもの。
- 例: プレイヤーA勝利、プレイヤーB敗北。
- 反例: 試験で80点を取ること。
- 関連語: バトル、HP、試召戦争、クラス代表。
- 実装・テストへの影響: 結果保存の冪等性、勝敗確定後の状態変更禁止をテストする。
- 未決事項: 引き分け、無効試合、切断負けを扱うか。

### 戦死

- 定義: 原作・アニメで、召喚獣の点数または戦闘継続力が0になり戦闘不能になる状態。
- アクター: 生徒、教師。
- 目的: 試召戦争からの一時退場と補習室送りを表す。
- 文脈: 原作・アニメ準拠の試召戦争、将来スコープ。
- ルール:
  - 原作・アニメでは戦死した召喚者は戦争終了まで補習室送りになる。
  - MVPではHP0を敗北として扱い、「戦死」という状態名は内部モデルに使わない。
- 含まないもの: アカウント停止、退学、成績0点の恒久保存。
- 例: 試召戦争中に召喚獣が倒される。
- 反例: 試験で0点を取っただけの状態。
- 関連語: HP、補習、試召戦争、勝敗。
- 実装・テストへの影響: 教育プロダクト上の表示文言として強すぎるため、MVPでは「敗北」「戦闘不能」を使う。
- 未決事項: 将来も「戦死」を用語として採用するか。

### 補習

- 定義: 原作・アニメで、戦死や戦闘放棄した生徒が受ける学習ペナルティ。
- アクター: 生徒、教師。
- 目的: 試召戦争のペナルティと学習機会を結びつける。
- 文脈: 原作・アニメ準拠の試召戦争、将来の学習支援。
- ルール:
  - MVPでは実装しない。
  - 将来実装する場合、罰ではなく学習支援タスクとして設計する必要がある。
- 含まないもの: 通常授業、試験そのもの、バトル履歴。
- 例: 敗北後に弱点科目の復習課題を出す。
- 反例: 単なるHP回復アイテム。
- 関連語: 戦死、補充試験、成績フィードバック。
- 実装・テストへの影響: 将来実装時は、生徒の心理的安全性と教育方針に合わせて名称・表示を検討する。
- 未決事項: 実教育導入で「補習」をペナルティ扱いにするか、復習セッション扱いにするか。

### 宣戦布告

- 定義: 原作・アニメで、クラス対抗の試召戦争を開始する申し込み。
- アクター: クラス、生徒、教師。
- 目的: クラス間の対抗戦を正式に開始する。
- 文脈: 将来の試召戦争、クラス設備攻略。
- ルール:
  - 原作・アニメでは上位クラスは宣戦布告を断れない。
  - MVPでは実装しない。
- 含まないもの: 1対1バトル作成、フレンド申請、通知。
- 例: FクラスがAクラスへ挑む申し込み。
- 反例: 教師が個人バトルを作成すること。
- 関連語: 試召戦争、クラス、クラス代表、クラス設備。
- 実装・テストへの影響: 将来実装時は、申し込み、受理、拒否不可条件、開始時刻、参加者確定を状態遷移として設計する。
- 未決事項: 教育現場向けに「宣戦布告」という名称を使うか、「対抗戦申請」に置き換えるか。
