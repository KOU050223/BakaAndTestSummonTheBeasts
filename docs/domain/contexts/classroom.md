# クラス編成コンテキスト

生徒、教師、クラス、所属、クラス設備を扱う文脈。

## 参照元

- Wikipedia「バカとテストと召喚獣」では、文月学園高等部は試験召喚システムを導入した高等学校で、成績によりAクラスからFクラスへ分けられる舞台として説明されている。
- 同ページでは、試召戦争の結果により上位クラスと下位クラスの教室設備が入れ替わるルールが説明されている。

## 用語

### 文月学園高等部

- 定義: 本プロダクトが参照する学校世界観の基準となる高等学校。
- アクター: 生徒、教師、学校管理者。
- 目的: 試験結果、クラス編成、召喚獣、試召戦争を同じ学校制度の中で扱う。
- 文脈: 学校設定、クラス編成、試験、バトル。
- ルール:
  - 原作・アニメでは試験召喚システムを導入した学校として扱われる。
  - 本プロダクトでは、実在学校に導入する教育支援プラットフォームのモデル校・世界観として扱う。
- 含まないもの: 実在する学校法人、実在校の成績制度。
- 例: 文月学園を模したデモ環境。
- 反例: ユーザーが実際に所属する学校そのもの。
- 関連語: クラス、試験召喚システム、試召戦争。
- 実装・テストへの影響: 将来、複数学校対応を行う場合は `school` 境界を追加する。
- 未決事項: MVPで学校エンティティを作るか、単一学校前提で省略するか。

### 生徒

- 定義: 試験を受け、点数に基づく召喚獣を持ち、バトルへ参加できる学習者。
- アクター: 生徒本人、教師、学校管理者。
- 目的: 学習成果を確認し、召喚獣やバトルを通じて学習意欲を高める。
- 文脈: クラス所属、試験結果、召喚獣、バトル参加。
- ルール:
  - 生徒は1つ以上のクラス所属を持つ。
  - MVPでは既存クラスに所属している前提とし、入学試験によるクラス振り分けは扱わない。
  - 生徒の召喚獣ステータスは、登録済み点数から再計算される。
- 含まないもの: 教師、学校管理者、召喚獣そのもの。
- 例: 2年Fクラスの生徒、数学バトルに参加する生徒。
- 反例: 採点だけを行う教師、システム設定だけを行う管理者。
- 関連語: ユーザー、クラス、点数、召喚獣。
- 実装・テストへの影響: 生徒が他生徒の非公開成績を閲覧できないことをテストする。
- 未決事項: 転校・休学・退学・年度更新時の所属履歴を扱うか。

### 教師

- 定義: 試験を登録し、点数を入力し、必要に応じてバトルや召喚の成立を管理する学校側の利用者。
- アクター: 教師。
- 目的: 生徒の学習成果を記録し、召喚獣ステータスとバトルの根拠データを整える。
- 文脈: 試験作成、採点入力、クラス管理、バトル作成。
- ルール:
  - MVPでは教師が採点済み答案の点数を手動入力する。
  - 原作・アニメの召喚フィールド展開者としての教師設定は、MVPではバトル作成権限として簡略化する。
- 含まないもの: 学校管理者、生徒、ゲームサーバー。
- 例: 数学試験を作成する教師、クラスの点数を確認する教師。
- 反例: 自分の点数だけを見る生徒。
- 関連語: 試験、点数、召喚フィールド、ロール。
- 実装・テストへの影響: 担当外クラス・担当外科目を操作できるかは権限仕様として分離してテストする。
- 未決事項: 教師の担当科目・担当クラスを必須で管理するか。

### クラス

- 定義: 生徒が所属し、成績・設備・試召戦争の単位になり得る学級。
- アクター: 生徒、教師、学校管理者。
- 目的: 生徒を管理し、成績確認や将来のクラス対抗戦の単位にする。
- 文脈: クラス編成、試験対象、試召戦争。
- ルール:
  - 原作・アニメではAクラスからFクラスまでの設備差を持つ階級的なクラスとして扱われる。
  - MVPでは既存クラスへの所属を前提にし、クラス設備の奪取・奪還は将来スコープとする。
- 含まないもの: バトルルーム、科目、ロール。
- 例: Aクラス、Fクラス、教師が試験対象に指定するクラス。
- 反例: 数学、英語、1対1バトル。
- 関連語: 生徒、クラス設備、クラス代表、試召戦争。
- 実装・テストへの影響: 試験作成時の対象クラス、クラス単位の点数一覧取得をテストする。
- 未決事項: 年次・組・A-Fランクを別項目にするか、表示名にまとめるか。

### クラス設備

- 定義: クラスに割り当てられる教室環境・備品のランク。
- アクター: 生徒、教師、学校管理者。
- 目的: 試召戦争の報酬・ペナルティとして、クラス対抗戦の意味を作る。
- 文脈: 原作・アニメ準拠の試召戦争、将来のクラス設備攻略。
- ルール:
  - 原作・アニメでは、上位クラス敗北時に下位クラスと設備が入れ替わる。
  - 下位クラスが敗北した場合は設備がさらに下がる扱いがある。
  - MVPでは実装しない。
- 含まないもの: 召喚獣ステータス、生徒個人の成績、画面テーマ。
- 例: Aクラス相当の設備、Fクラス相当の設備。
- 反例: 生徒のHP、バトル中のフィールド。
- 関連語: クラス、試召戦争、勝敗。
- 実装・テストへの影響: 将来実装時は、試召戦争結果と設備履歴を同一トランザクションで反映する。
- 未決事項: 実教育導入時に設備格差を本当に表現するか、ゲーム内報酬へ置き換えるか。

### クラス代表

- 定義: クラス対抗の試召戦争で、勝敗決定の対象になり得る生徒。
- アクター: 生徒、教師。
- 目的: クラス対抗戦の勝敗条件を明確にする。
- 文脈: 試召戦争、クラス対抗戦。
- ルール:
  - 原作・アニメでは、クラス代表の敗北が戦争の勝敗決定条件になる。
  - MVPの1対1バトルでは扱わない。
- 含まないもの: ロール、学校管理者、通常のプレイヤー。
- 例: Fクラス代表として戦う生徒。
- 反例: 個人バトルの参加者、教師。
- 関連語: クラス、試召戦争、勝敗。
- 実装・テストへの影響: 将来実装時は、代表の選出・変更・公開義務を状態として扱う。
- 未決事項: 代表を教師が指定するか、クラス内投票・固定設定にするか。
